# V18 continuous illustration skinning

`visual_v18.json` takes precedence over the V1 component registrations. Each of the five performers uses its final original PNG from `assets/art/visual_v18`, sampled once on one shared-vertex triangle surface. No PNG pixels are changed, no full-body image is drawn behind the mesh, and the renderer creates no extra body, shadow clone or second weapon.

The joints/semantic regions in the art agent's final `visual_v18/metadata.json` are the fitting reference. Rig weights and IK are presentation estimates, not independent artwork frames. The JSON-only builder is `work/hd-v18/build_mesh_metadata.py`; it never opens or rewrites an image. Each performer has separate controls for head, torso, upper/lower limbs and fixed feet. Cat adds its tail; shark adds tail, fins and all three shoes; worker carries the briefcase; chicken carries the basketball and has delayed center-part hair; Rio has separate twin tails, two skirt regions and an independently grounded heavy blade. Both Rio arms follow the same blade through IK. Her body rocks toward the blade rather than stretching fully extended painted arms away from it.

The public renderer API remains `has_assets`, `draw_character`, `get_pose_state`, and `get_content_rect`. `body_height` is final metadata's body height in source pixels scaled to the requested display height, not the entire weapon-width bounding box. `source_foot` is art's perspective ground anchor; `feet` preserve each painted contact's original perspective offset. No per-frame bounding-box scaling occurs. Source-facing `1` leaves the master unflipped; Rio's blade points down/right. Only the draw transform mirrors the other facing.

`idle`, `dance`, `invite`, `confirm`, and `easter` are continuous local poses. UI supplies its existing 160 BPM music clock: dance .75 seconds per cycle, idle 2.25 seconds, and half-beat cast offsets. Confirmation holds from .55 progress. Reduced motion freezes the UI's requested loop pose and retains immediate discrete feedback. These are controlled local menu gestures and breathing, not a claim of full independently painted animation sequences or large combat action coverage.

Runtime pose meshes are bounded to 32 total, reused regardless of display height or facing. Source textures/layouts load once per character. `release_cache()` tears down these caches. The existing hidden-page UI gate prevents pose/drawing work while retaining reaction timers.

Validation: `tests/hd_master_mesh.gd` checks actual vertex/UV/index arrays, exact neutral source correspondence, one-time UV coverage, positive triangle areas, fixed painted foot contacts, hand/grip continuity and bounded caches. `tests/hd_menu_performers.gd` retains production menu interaction/reduced-motion/hidden-page/lifecycle tests and branches only its old separate-parts assertion for the new single-surface renderer. Old `tests/hd_character_rig.gd` contains V1-specific choreography landmarks/stepping assertions and is historical V1 coverage; it is not the new master's motion contract.

Native evidence: `work/hd-v18/final-<id>-<clip>.png` renders four actual phases of each of five clips for all five performers, 100 poses total. No native warning was observed. Combined UI layout and animation captures are owned by Root/UI.
