# 原四角色のフレーム領域

`shark`、`cat`、`worker`、`chicken` の `core` / `special` 原本 PNG は変更していません。AI が描いた姿勢は名目上の等分セルを越える場合があるため、8 個の `*.frames.json` が実際の人物領域を指定します。PNG の再生成・切り取り・マスク画像の作成は行っていません。

## データ契約

- `version: 1`、`canvas: [width, height]`、`columns: 4`。
- `core` は 8 行・32 フレーム、`special` は 4 行・16 フレーム。`frames` は行優先で `frame = row * 4 + col`。
- `actual_rect: [x, y, width, height]` は元 PNG の絶対ピクセル座標。人物、付属物、動作線の共同境界です。
- `source_parts` があれば、同じ元 PNG 内の複数の長方形を描画します。各 part は `actual_rect` 内で互いに重ならず、同じ倍率・座標変換を使います。内部の境界は人物を横切る場合がありますが、元の連続した画素を隙間なく描画します。
- `row_calibration.foot_line` は PNG 全体の絶対 Y 座標。`center_x` は名目セル内のローカル X 座標。4 フレーム共通で使用します。
- `body_height_unit` は立った身体の基準ピクセル高。腕、鞄、ボール、尾などを含む個別フレームの境界高ではありません。描画倍率は行単位で固定し、フレームごとの bbox 正規化はしません。
- `anchor_px` は診断用の絶対座標です。実描画では各行共通の `foot_line` と `center_x` を使います。

## 抽出方法

読み取り専用の画像分析で alpha > 192 の連結成分から人物の対応を決め、alpha > 38 の完全な連結成分まで輪郭を復元しました。距離制限で薄い輪郭を途中で切らず、独立した 80 ピクセル以上の動作線・付属物も対応する姿勢に含めています。投げた本と発射したボールは動作の意味に従って所有フレームを決めています。

通常は輪郭に 3 ピクセルの外側余白を含む 1 長方形です。共同 bbox に隣の姿勢や孤立した未帰属の点が入る場合だけ、互いに重ならない `source_parts` に分割します。最も複雑なフレームは `shark_core` の 17 番で 12 parts です。すべて同じ元ピクセル倍率で描画するため、部分ごとの伸縮はありません。

`atlas-frame-metadata-qa.json` は全 192 フレームについて、割り当てた alpha > 38 輪郭の欠落が 0、描画領域内の他姿勢の alpha > 38 画素が 0 であることを記録しています。これは元画像を加工せず、描画する領域のみを選択した結果です。

## 固定身体尺度

| Character | Core source body px | Special source body px |
| --- | ---: | ---: |
| shark | 153 | 185 |
| cat | 199 | 297 |
| worker | 203 | 285 |
| chicken | 174 | 277 |

各シート内の全行は表の固定尺度を使います。行ごとの共通足点と中心点の数値は各 `*.frames.json` が正です。新しい `cat_super.png` と Rio の独立クリップは専用の固定尺度を使用し、この旧シートの値を適用しません。

## 検証

Godot の実際の reader は **1652 / 1652 checks** を通過しました。alpha 境界条件と source parts の連続性条件を緩めていません。5 人の OpenGL 実機画面で待機、蹲下、投げ、必殺技を確認し、さらに最終の重攻撃命中、鞋鮫の超必殺演出、猫の超必殺演出を目視確認しました。頭・手・足・武器の硬い切断や parts の継ぎ目は見られず、身体倍率と地面の足点は追加変更不要でした。

再現用抽出スクリプトはプロジェクト外の `work/extract-atlas-metadata.py`、実機画像は `work/combat_test/` にあります。スクリプトが書き出すのは JSON だけで、画像ファイルは保存しません。
